# 推敲 (suikou)

Chrome で読む場合は [README.html](README.html) を開いてください。

note でエッセイや小説を書く人のための、**校閲・編集者視点の指摘ツール**。

AI に書かせるためのツールではありません。書き上げた原稿を外から眺めるための鏡です。
このツールは答えを出しません。**指摘と、考えるための視点だけを返します。**

---

## 使い方

`index.html` をダブルクリックしてブラウザで開くだけです。インストールもビルドも不要です。

ブラウザの設定でローカルファイルの読み込みが制限されている場合は、同梱のサーバーを使ってください。

```powershell
powershell -ExecutionPolicy Bypass -File .\serve.ps1
# http://127.0.0.1:8787/ を開く
```

ルールが意図どおり動いているかは `test.html` を開くと確認できます（93 項目の自己テスト）。

### キーボード

| キー | 動作 |
| --- | --- |
| `Ctrl` + `Enter` | 待たずに即時解析 |
| `F8` / `Shift` + `F8` | 次 / 前の指摘へ移動 |
| `Ctrl` + `S` | 本文を Markdown で保存 |
| `Ctrl` + `Shift` + `P` | note風プレビューと執筆画面の切り替え |
| `Ctrl` + `Shift` + `L` | 明るいテーマ / 暗いテーマ |
| `Ctrl` + `Shift` + `F` | 集中モード（指摘パネルを隠す） |

原稿と設定はブラウザの localStorage に自動保存されます。テーマは右上の `☾` / `☀` でも切り替えられ、既定は明るいテーマです。

### タブレット・スマホ

幅が広い画面（PC や、横向きのタブレット）は、これまでどおり執筆と指摘が並びます。

幅がおよそ 720px 以下（スマホや、細いウィンドウ）では、下の「執筆」「指摘」で画面を切り替えます。プリセットや取り込みは右上の「メニュー」に入っています。指摘をタップすると執筆側の該当箇所へ移ります。

同じアドレスを開いても、原稿は**その端末のブラウザの中**に保存されます。PC で書いた下書きは、スマホには自動では出ません。

### GitHub で公開する（スマホの Chrome で開く）

アプリのファイルだけを GitHub Pages に置くと、`https://（アカウント）.github.io/（リポジトリ名）/` で開けます。原稿は GitHub に上がりません。解析も端末の中だけです。

1. GitHub で新しいリポジトリを作る（無料なら **公開** にする。非公開の Pages は有料プランが必要です）
2. このフォルダ一式をそのリポジトリに上げる（ビルドは不要です）
3. リポジトリの **Settings → Pages** で、Source を **Deploy from a branch**、Branch を `main`（または `master`）の `/ (root)` にする
4. 数分待つと URL が出ます。タブレット／スマホの Chrome で開き、ブックマークします

ルートに `.nojekyll` を置いてあるので、Jekyll にファイルを消されません。`index.html` や `src/` のパスは相対指定のままなので、サブフォルダ型の Pages（`…github.io/リポジトリ名/`）でも動きます。

## 設計の前提

### 1. 既定では通信しない

69 のルールはすべて辞書と規則で、この端末の中だけで動きます。既定の状態でネットワークに出ることは一切ありません。

これは技術的な妥協ではなく、要件から出た結論です。

- **R-18 を含むどんな原稿も、検閲も送信もされない**
- 未公開の原稿が第三者のサーバーに残らない
- なぜ指摘されたのかが全部読める（`src/core/dict-language.js` を見れば根拠がわかる）
- オフラインで動き、無料で、API の仕様変更で壊れない

規則で扱えないのは文意です。そこだけを言語モデルに読ませる口を別に用意しました（「AI 補助」の節）。**既定はオフ**で、有効にしてもボタンを押した瞬間しか送信しません。

### 2. 本文を書き換えない

自動修正機能はありません。言い換え候補は出しますが、置換ボタンは付けません。候補はクリックでコピーできるだけです。

さらに既定では**候補を伏せています**（設定で変更可）。「候補を見る」を押すまで表示されないので、まず自分の言葉で考えられます。

例外は表記統一だけです。「できる／出来る」の統一は機械的な作業なので、設定でオンにすると一括置換ボタンが出ます。既定はオフです。

### 3. 「間違い」と「気になる箇所」を分ける

指摘は 4 段階です。

| 段階 | 意味 |
| --- | --- |
| 要修正 | 直したほうがいい。誤字、括弧の閉じ忘れ、個人情報の混入など |
| 検討 | 読者がつまずく可能性がある。長文、表記の揺れ、重言など |
| 確認 | 意図的ならそのままで構わない。同音異義語、受け身の多用など |
| 参考 | 気づいていないかもしれない傾向。五感の偏り、語彙の多様性など |

### 4. 見た指摘は消せる

指摘を残したまま作業すると、同じものを何度も読み返すことになります。各カードに 2 つのボタンがあります。

| ボタン | 動作 |
| --- | --- |
| ✓ 対応済み | 直した・読んだ指摘を隠す。ルールと当たった語、その前後 4 文字で同一性を判定するので、**別の場所を編集しても印が外れません** |
| ⊘ 今後も無視 | ルールと語の組み合わせで登録する。別の原稿でも出なくなる（誤検知を殺すためのもの） |

隠した指摘はフィルタの「片付け済み」で呼び戻せます。まとめて戻すには設定タブの「片付けた指摘」を使ってください。

## note との受け渡し

note のインポートは WXR形式（WordPress の XML）と MT形式（MovableType の txt）、エクスポートは WXR + `assets` フォルダの ZIP です。これに合わせて、日常用と一括用の 2 経路を用意しています。

### 推敲記法

note の各ブロックと 1 対 1 で対応する記法です。エディタ直上のバーで、選択した行に見出し・引用・箇条書きなどを付けられます。もう一度押すと外します。見出しや引用の操作は Ctrl+Z で戻せます。画像はエクスプローラーから選ぶか、貼り付け・ドロップで入れます（プレビューでは見えますが、note へ渡すときは note 側で貼り直してください）。

| 記法 | note のブロック |
| --- | --- |
| `# 見出し` | 見出し（大） |
| `## 見出し` | 見出し（小） |
| `> 引用` | 引用 |
| `- 項目` / `1. 項目` | 箇条書き / 番号付きリスト |
| `**太字**` | 太字 |
| `---` | 区切り線 |
| `[目次]` | 目次ブロック |
| `![説明](URL)` | 画像 |
| URL だけの行 | 埋め込みカード |
| `｜漢字《ふりがな》` | ルビ |
| ` ``` ` | コード |
| `===有料ライン===` | 有料エリアの境界（目印） |

### note → 推敲

- **note のエディタからコピーして貼るだけ**。クリップボードの HTML を読んで、見出し・引用・箇条書き・太字・ルビ・画像・埋め込みを上の記法に置き換えます。引用は `<blockquote>` のほか、class / data-name に quote が付いた箱も拾います。表は note にないので箇条書きに落とします。
- タイトル横の「消す」で、確認のあとタイトルと本文を空にします。
- note のエクスポートで届く ZIP を解くと XML が出てきます。「取り込み ▾ > note のエクスポートを開く」で読むと記事の一覧が出るので、推敲したい記事を選べます。MT形式の txt も読めます。

### 推敲 → note

| 方法 | 使いどき |
| --- | --- |
| **note用HTMLをコピー** | 日常用。note のエディタに貼ると装飾がそのまま反映されます |
| WXR形式で保存（.xml） | note の 設定 > インポート に読ませる。**下書きとして入ります** |
| MT形式で保存（.txt） | WXR で通らなかったときの代替 |
| 文字だけコピー | 記号を外した素の本文 |

note 側の制約はこちらでは超えられません。手元の画像は note で貼り直す必要があり（取り込まれるのは `src` が http(s) の URL の画像だけ）、埋め込みは URL のテキストとして入ります。インポートの結果は開始から 3 日以内にメールで届きます。

### note風プレビュー

タイトル欄の下の「note風プレビュー」で、note に載せたときの見え方に切り替わります。目次ブロック・埋め込みカードの位置・有料ラインもそのまま出るので、スマホでの改行位置や画像の間隔を原稿の段階で確認できます。指摘をクリックすると、プレビュー中はその段落が強調されます。

### 「note で使えない記法」の扱い

以前は `#` や `**` を「文字として残る」と警告していましたが、上の経路では記法が note のブロックに変換されるので、既定では黙っています。設定タブの「note への渡し方」を「文字だけ貼る」にすると、記号が残る前提の指摘が復活します。

note に対応機能がないもの（表・脚注・斜体・取り消し線・3 階層以上の見出し・入れ子リスト）は、渡し方にかかわらず警告します。

## 何を見ているか

69 のルールが 8 つのカテゴリに分かれています（AI 補助を有効にすると 9 つ目の「AIの指摘」が加わります）。すべて設定タブで個別にオン／オフ、深刻度の変更、閾値の調整ができます。

### 誤字・誤用
明確な誤字（慣用句の誤り、外来語の綴り）、ら抜き・さ入れ言葉、二重敬語、重言、同音異義語の取り違え、助詞の打ち間違い、括弧の対応、半角カナ・全角英数、三点リーダの表記、副詞の呼応（決して〜ない、たとえ〜ても）。

### 表記の揺れ
辞書ベース（できる／出来る、こと／事、ください／下さい など約 60 グループ）と自動検出（長音・中黒・大小文字の違いだけで一致するカタカナ語・英単語）。敬体と常体の混在、一人称の混在、数の表記、句読点のスタイル。

### 表現・違和感
一文の長さ、読点の密度、文末の同形連続（〜た。〜た。〜た。）、同じ語の近接反復、文頭の接続詞、「の」の三連続、「〜て、〜て」の連鎖、受け身の多用、二重否定、指示語の多用、冗長な言い回し、強調語・ぼかし表現・前置きの多用、主語と述語の距離、体言止めの連続、い抜き言葉、括弧による補足の多用。

### 語彙・単調さ
頻出内容語の検出と言い換え候補（約 70 語の同義語辞書）、抽象語・漢語の多用、**五感の偏り**（視覚に寄りすぎて音や匂いがない状態）、語彙の多様性（TTR）。

### 構成・リズム
段落の長さ、文の長さの単調さ、**冒頭の掴み**（挨拶で始まっていないか、一文目が長すぎないか、具体物があるか）、結びの弱さ、見出しの間隔。

### note 最適化
- 文字数と読了時間（note で読まれやすい帯）
- **note に対応機能がない記法**（表、脚注、斜体、取り消し線、3 階層以上の見出し、入れ子リスト）
- 文字だけで貼る設定のときだけ出る記法の指摘（`#`、`**`、`[]()`、`>`）
- 空行の使い方（スマホでの文字の壁）
- 視覚要素の間隔（画像・引用・箇条書きが出てこない区間）
- タイトルの診断（長さ、具体性、本文との語の重なり）
- ハッシュタグの数（既定オフ。タグは公開時に note 側で付ける前提）
- **有料記事の無料部分**（割合、問いで切れているか）
- 文中の生 URL（単独行に置けば埋め込みカードになる）

### レーティング
レーティングは「全年齢（厳格）」「全年齢」「R-18」の 3 段。詳細は次節。

### リスク・配慮
実在の人物・団体への言及、個人情報（電話番号・メール・住所・カード番号）の混入、配慮したい表現の言い換え（報道・出版の用語集ベース）、根拠のない断定、ユーザー禁止語。

## レーティングの扱い

### 全年齢モード
性的・暴力的に読まれうる語を拾い、「示唆にとどめる」方向の視点を返します。削れとは言いません。

### R-18 モード
**性的表現そのものは指摘しません。** 代わりに、実際に問題になる 3 点を見ます。

1. **未成年を示す語と性的文脈の共起** — 最優先の検査です。「高校生」「制服」「17歳」などの学齢を示す語が性的な文脈の近くにある場合、規約・法令上の重大なリスクとして警告します。冒頭に成人であることの明示があれば警告を弱めます。
2. **ゾーニング** — 冒頭 400 字に注意書きがあるか。タグで識別できるか。**冒頭 150 字に直接的な語がないか**（一覧カード・検索結果・SNS シェアでは冒頭が全年齢に露出します）。
3. **表現の単調さ** — 官能描写は語彙が反復しやすい領域です。同じ感覚語の繰り返しを拾い、感覚の対象を変える方向（音→温度→時間の感覚）を提案します。

公開前チェックリストも読者像タブに出ます。

### 露骨な語について
このツールの辞書に露骨な語は入れていません。検出したい語は「設定 > ユーザー辞書 > 追加で検出したい語」に自分で登録してください。登録した語は未成年描写との共起チェックにも使われます。

## AI 補助（任意・既定オフ）

規則で扱えるのは表層です。論理の飛躍や主張と根拠のずれは、意味を読まないと判定できません。そこだけを言語モデルに渡す口が設定タブにあります。

### 何を任せるか

AI に聞くのは次の 7 点だけです。誤字・表記の揺れ・句読点は**プロンプトで明示的に禁じています**。規則のほうが速く、確実で、根拠が読めるからです。

1. 論理の飛躍（前提が示されないまま結論に進んでいる箇所）
2. 主張と根拠の不一致
3. 段落間のつながりの欠落
4. 事実確認が必要な断定
5. 話題の重複
6. タイトルや冒頭で与えた期待と本文のずれ
7. 読者が誤読しうる箇所（主語の取り違え、指示語の曖昧さ）

返ってくるのは指摘だけです。書き換え文は求めていません。指摘は「AIの指摘」カテゴリとして通常の一覧に混ざり、対応済み・無視も同じように使えます。

### リスクと、それへの対処

| リスク | 対処 |
| --- | --- |
| 未公開原稿が第三者のサーバーに残る | **既定オフ。ボタンを押した瞬間しか送信しない。送る内容は事前に全文表示して確認を取る** |
| 成人向け原稿が提供元の規約に触れる | **R-18 レーティングでは localhost 以外への送信をブロック**（設定で明示的に解除しないかぎり通らない） |
| 生成 AI の内容フィルタで拒否される・警告される | ローカルのモデルなら起きない。この設計ではローカルを既定にしている |
| 出力が毎回変わる／もっともらしい嘘を返す | 「参考」相当の扱い。規則の指摘とは別カテゴリに分けて混ぜていない |
| API の仕様変更や課金で壊れる | ルールエンジンは AI に一切依存していない。AI を切っても機能は減らない |

**結論として、外部の API より、この端末でモデルを動かすほうを勧めます。** 接続先は OpenAI 互換の `/chat/completions` なので、Ollama・LM Studio・llama.cpp server がそのまま使えます。日本語の校閲なら 14B 前後のモデルで実用になります。

```
Ollama    : http://localhost:11434/v1/chat/completions
LM Studio : http://localhost:1234/v1/chat/completions
llama.cpp : http://localhost:8080/v1/chat/completions
```

ブラウザから localhost に通信するには、モデル側で CORS を許す必要があります。Ollama なら環境変数 `OLLAMA_ORIGINS` を `*` にして起動し直してください。`serve.ps1` で開いていると通りやすくなります。

API キーは localStorage に平文で残ります。共有端末では入れないでください。

## 誤検知について

校正ツールは、誤検知が多いと読み飛ばす癖がついて役に立たなくなります。この版で入れた対策は 3 つです。

1. **複合語ガード** — 漢字で始まる語の直前が漢字なら、複合語の一部として捨てます。「慢性的」「個性的」の中の「性的」、「見殺し」の中の「殺し」がこれで消えます。「主人公」の「主人」のように末尾側で判定が必要なものは、後続も見ます。
2. **除外語リスト** — 「裸足」「忙殺」「殺風景」のように、ガードでは拾えないものを `dict-rating.js` の `exclusions` に並べています。ヒットがその語に完全に含まれるときだけ捨てます。
3. **確実なものだけ見る** — 助詞の打ち間違いから「のの」を外しました。「〜しなかったものの」「ののしる」に当たるためです。取りこぼしても、誤検知しないほうを選んでいます。

それでも自分の文章に特有の誤検知は出ます。そのときは指摘カードの「⊘ 今後も無視」を押してください。ユーザー辞書の「指摘しない語」に固有名詞を登録するのも有効です。

## 読者像の推定

書き上げた文章を計量して、「誰に向いた文章になっているか」を逆算します。当てにいくのではなく、自分の文章を外から見るための材料です。

- **8 軸のプロファイル** — 硬さ / 距離の近さ / 内省 / 抽象度 / 具体物の密度 / 感情の量 / 対話性 / 読解の負荷
- **ジャンル推定** — エッセイ・日記・評論・実用・レビュー・小説・技術・ビジネス・詩の 9 分類
- **想定読者** — 年齢帯、読解水準、トーン、読まれる場面（通勤中か、夜に腰を据えてか）
- **噛み合っていない点** — 「抽象度が高いのに具体物が少ない」「読者に近い口調なのに内面が書かれていない」といった内部矛盾
- **頻出語**

診断タブには段落ごとの**読みの負荷ヒートマップ**もあります。文字量・文長・漢字率から、読者がどこで止まりやすいかを可視化します。クリックでその段落へ飛べます。

## プリセット

| プリセット | 用途 |

| エッセイ（全年齢・標準） | 標準。校正は厳しく、表現は提案どまり |

## ユーザー辞書

誤検知を殺せないと校正ツールは使い物になりません。5 種類を登録できます。

| 種類 | 書式 | 用途 |
| --- | --- | --- |
| 指摘しない語 | 1 行 1 語 | 固有名詞、造語、キャラクター名。この語を含む箇所は全ルールの対象外 |
| 表記の統一ルール | `推敲 = 推稿, すいこう` | 自分の表記ルールを強制する |
| 自分用の言い換え候補 | `美しい = 端正だ, 目を奪う` | 内蔵辞書に自分の語彙を足す |
| 使わない語 | 1 行 1 語 | 自分で禁じた語。「要修正」で出る |
| 追加で検出したい語 | 1 行 1 語 | レーティング用。R-18 の共起チェックにも使われる |

`src/ui/` の各ファイルは `Suikou.ui` に関数を足していく形で、DOM 参照 (`Suikou.ui.el`) と状態 (`Suikou.ui.state`) を `state.js` の1箇所だけで持ちます。他ファイルの関数は呼び出す瞬間に `Suikou.ui` から引くので、読み込み順に縛られません。

`preview.js` だけは DOM を組み立てます。それ以外の `src/core/` は DOM に一切触れません。ブラウザの外（Node など）でも動くよう、`globalThis.Suikou` と `module.exports` の両方に載せています。将来 CLI を足すなら、この層をそのまま使えます。

## ルールを自分で足す

辞書に足すだけなら `dict-language.js` の配列に 1 行増やすだけです。ルールを足す場合は次の形で登録します。

```js
Suikou.registerRule({
  id: 'my.rule',
  name: '自分のルール',
  category: 'expression',        // typo / consistency / expression / vocabulary
                                 // structure / note / rating / risk
  severity: 'info',              // error / warn / info / hint
  description: '設定画面に出る説明。',
  params: [
    { key: 'limit', label: '上限', type: 'number', value: 3, min: 1, max: 20, step: 1 }
  ],
  ratings: ['r18'],              // 省略可。特定レーティングだけで動かす場合
  run: function (ctx, add, params) {
    Suikou.util.scan(ctx.text, /パターン/g, function (m, idx) {
      add({
        start: idx,
        end: idx + m[0].length,
        message: '何が起きているか。',
        advice: '書き手が自分で考えるための視点。',
        suggestions: ['候補']    // 省略可
      });
    });
  }
});
```

`ctx` には `text` / `title` / `hashtags` / `sentences` / `paragraphs` / `headings` / `config` / `dictionary` が入っています。`index.html` にスクリプトタグを足し、`test.html` に検証を書いてください。

## 限界

- 形態素解析器を使っていないので、語の切り出しは文字種の切り替わりによる近似です。漢字の複合語は塊で扱われます。
- 規則だけでは文意を理解しません。論理の飛躍や事実誤認は、AI 補助を自分で有効にしたときだけ見られます。有効にしても、返ってくるのは確率的な指摘であって正解ではありません。
- 同音異義語の指摘は「確認」レベルです。文脈から確実に判定できるものだけを拾っています。
- 読者像の推定は計量からの逆算です。統計的な裏付けのあるモデルではなく、自分の文章を眺めるための道具として使ってください。
- WXR / MT 形式の書き出しは仕様に沿って組んでいますが、note のインポーターに対する実機検証はしていません。通らなかった場合は、日常用の「note用HTMLをコピー」を使ってください。
- note の HTML 構造は予告なく変わります。貼り付けの取り込みは一般的な HTML の構造（`h2` / `blockquote` / `ul` など）に対して書いてあるので大きくは壊れませんが、note 固有の新しいブロックは文字として入ります。
